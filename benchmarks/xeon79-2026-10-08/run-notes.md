# Run notes

- Native x86-64 server: `jinhelin@10.2.12.79`, repository at `/DATA/disk1/jinhelin/github/memtable-bench`.
- All nine adapters compiled with GCC 11.3.1 in Release mode. Build/configure commands unset all upper/lower-case HTTP, HTTPS and ALL proxy variables. No formatting target was run.
- The first attempted warmup exposed a harness NUMA syscall bug and exited before formal data collection. Its remote directory is `results/xeon79-2026-10-08`. The complete comparison uses the fresh `results/xeon79-2026-10-08-r2` directory. The failed warmup is excluded.
- The old code passed `numa_node + 1` as `set_mempolicy`'s `maxnode`. On this Linux kernel, `maxnode=1` with the node-0 mask returns `EINVAL`; 2, 64 and 65 succeed. Linux subtracts one before interpreting the mask. The corrected code passes one unsigned-long word's bit capacity plus one, following libnuma. See [Linux v5.14 get_nodes](https://github.com/torvalds/linux/blob/v5.14/mm/mempolicy.c#L1288) and [libnuma](https://github.com/numactl/numactl/blob/master/libnuma.c).
- All 10 tests passed again after this fix, including all-adapter workload tests with `MEMTABLE_BENCH_TEST_NUMA_NODE=0`, CPUs 2,3,4,5 and the required HOT runtime check. Evidence: `numa-rebuild-tests.log`.
- `placement-sample.txt` captures one process during prefill: CPU 2 and `bind:0` anonymous mappings resident on N0. The `Mems_allowed_list=0-1` field is the process's allowed cpuset, not the selected memory policy. Worker pinning is implemented by the harness; the runner verifies that its selected CPUs are distinct physical cores on node 0.
- L1D/LLC/DTLB counters use perf's generic **read miss** events; branch misses are branch events. These are per-operation event counts, not miss percentages. Events are scaled independently by enabled/running time. Blank fields mean no measurement was obtained, which can occur in short phases.
- The benchmark includes logical key creation, codec conversion, record ownership, synchronization, value copies, cursor/checksum work and one-in-64 latency sampling. It compares these adapters under the stated contract. It does not isolate the minimum theoretical cost of each indexing algorithm.
- `benchmark-source.tar.gz` contains the exact harness/adapter/CMake/patch/script sources recorded in `source-manifest.json`. Dependency HEADs and the binary SHA256 are in `metadata.json`; build configuration is in `build-config.txt`. Source changes made after the run are not part of that archived measurement snapshot.

- TLX pin `502601e2328129263eeb31a61342e4a48f519a2b` is the annotated v0.6.1 tag object, which peels to the recorded HEAD `b6af589954fafd334f2f373b057a8886e1c6abc8`; these identify the same sources. Verified with `git cat-file -t` and `git rev-parse <tag>^{commit}`.
